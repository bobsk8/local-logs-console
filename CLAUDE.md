# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

`local-log-viewer` (marketplace display name "Local Logs Console", publisher `bobsk8`) is a VS Code extension that captures local application logs — either by running a command and streaming its stdout/stderr, or by tailing an existing log file — and renders them in a filterable webview dashboard. No proposed VS Code APIs are used (Marketplace compatibility) and no logs leave the machine. The extension declares `untrustedWorkspaces.supported: false` (it executes arbitrary shell commands) — keep it that way.

## Commands

```bash
npm install
npm run compile     # clean out/ + media/, tsc (host), webview typecheck, esbuild bundle
npm run watch       # parallel tsc -watch (host) + esbuild --watch (webview), used by F5
npm run lint        # ESLint flat config (eslint.config.mjs) — host and webview blocks
npm test            # compiles + build:test-libs, then test/run-all.js runs every test/test-*.js
npm run package      # builds a .vsix via @vscode/vsce (prepublish = production/minified build)
```

- Run the extension: press **F5** in VS Code ("Launch Extension" in `.vscode/launch.json`), which starts the `watch` task and opens an Extension Development Host.
- There is **no test framework** — tests are plain-Node assertion scripts (`test/test-*.js`) run by `test/run-all.js` against compiled output (`out/` for host and shared modules, `out/test-libs/` for the bundled webview libs), so you must `npm run compile` after any `src/` change before testing. Suites: parser, timestamp, stackFrames, sourceResolver, projectScripts, webview UI libs (suggest/highlight/delta), commandStore, logStore, logPipeline, pasteImport, redactor, lineCleaner, lineSplitter, fileTail (real temp files, stubbed vscode), processTree, regexSafety, search, exporter, webview filter/format, mcp-protocol, mcp-tools, mcp-setup, mcp-server (integration, stubbed vscode). `run-all.js` runs every suite and prints a summary even when one fails. A new `test/test-*.js` file is picked up automatically. `scripts/mcp-smoke.sh <port> <token>` runs live curl checks against an F5 session.
- CI (`.github/workflows/ci.yml`) runs lint + compile + test + `vsce package` on ubuntu/macos/windows — cross-platform behavior matters (see process termination below).
- `docs/demo.gif` is documentation only (referenced by absolute URL in README) — do NOT move it back into `resources/`, and keep `files` as an explicit icon allow-list or the VSIX balloons back to 4 MB.

## Architecture

The extension has two runtime sides that communicate only through VS Code's webview `postMessage` bridge.

**Extension host (TypeScript, compiled to `out/`):**

Every captured line flows through one path: capture source → `LogPipeline.ingest` (clean → redact → parse → tag) → `LogStore` (history) + `LogEventBus` (live fan-out) → subscribers (`LogDashboard`). Capture sources never write to the dashboard directly.

- `src/extension.ts` — thin composition root: instantiates the services below, registers commands, wires the status bar (shows active-capture count) and disposal.
- `src/core/logPipeline.ts` — the single ingest path. Owns the `Redactor` (rebuilt on config change via `refreshConfig()`). **`openStream(opts)`** returns a `LineSink` (`push`/`end`) — the path every capture source uses (command stdout/stderr, file tail, paste): clean → redact → assemble multi-line events → parse → store + bus; `push()` returns the redacted text so command capture can echo it to the terminal. `ingest()` / `ingestPrepared()` remain for single, ungrouped lines (exit summaries, tests). Assigns `LogEntry.seq` (monotonic). Stream defaults: stderr lines are INFO with `stream: "stderr"` — never assume stderr means error.
- `src/core/captureManager.ts` — `runAndCapture()` inside a `vscode.Pseudoterminal` (output visible in terminal *and* forwarded to the pipeline). Owns `runningChildren`/`mutedProcessPids` and honors `localLogViewer.capture.inheritEnvironment` (minimal env when off; host-only vars like `ELECTRON_RUN_AS_NODE` are always stripped). The pty has no line discipline, so it echoes input and turns Enter into `\n` itself. On exit it ingests a structured `event: "exit"` entry (ERROR when the code is non-zero) and keeps the terminal open until a keypress.
- `src/core/lineAssembler.ts` — pure `LineAssembler`: groups a line stream into events (stack frames, `Caused by:`, Python tracebacks closed by their exception line, Go frames, indented lines under ERROR/WARN heads, `{`…`}` dumps; capped at 200 lines). `LogPipeline.openStream()` owns one per source and flushes a pending event after 150 ms of silence. The pipeline stores continuation lines in `LogEntry.stack` (a traceback's message becomes its exception line) and raises the level from the stack.
- `src/core/lineSplitter.ts` — pure `LineSplitter`: bytes → lines with a `StringDecoder` (multi-byte UTF-8 safe across chunks), CR/CRLF handling and a 64 KB line cap. Used by both command capture and file tail.
- `src/core/fileTail.ts` — `FileTailManager`/`TailSession`: `fs.watch` plus a `fs.watchFile` polling safety net; reads are **serialized** (one ranged stream at a time) so lines never interleave. Truncation resets the offset; rotation (inode change / delete + recreate) reopens from 0. The seed (`localLogViewer.tail.seedBytes`) drops its leading partial line. `TailSession` takes a structural sink so `test/test-file-tail.js` drives it with real temp files.
- `src/core/pasteImport.ts` — `importPastedText(pipeline, text, label)`: splits pasted text into lines, feeds each through `LogPipeline.ingest()` (raw path, includes clean/redact/parse). **Deliberately NOT registered in `SessionRegistry`** — pasted snapshots have no `stop()` semantics. Entries are tagged with a synthetic `paste-N` sessionId for grouping/filtering.
- `src/core/processTree.ts` — cross-platform tree termination (see bites). Exports pure `parsePsTable()` for tests.
- `src/core/debugCapture.ts` — `DebugCaptureManager`: a `registerDebugAdapterTrackerFactory('*')` tracker turns DAP `output` events (stdout/stderr only — `console` is the debugger talking) into a `kind: 'debug'` session keyed by the top-level debug session (child sessions share it). Stop = `stopDebugging`, restart = `startDebugging` with the same configuration. Setting `capture.debugSessions`.
- `src/core/sourceResolver.ts` — vscode-free `SourceResolver`: maps a printed frame path (absolute, relative to the capture cwd or a root, container `/app/...` tails, Java bare names via an injected finder) to a file **inside the workspace roots or the capture cwd only** — a log line is untrusted text. Cached; `reset()` on file create/delete.
- `src/core/problemsReporter.ts` — ERROR entries whose first in-app frame resolves become `Diagnostic`s (deduped per line+message, capped per file and in total); cleared on `store.onDidClear` and when a session with the same label starts again. Setting `problems.enabled`.
- `src/core/redactor.ts` — pure `Redactor` class masking secrets (AWS/GitHub/Slack/Google tokens, JWTs, bearer tokens, URL credentials, password-ish key/value pairs) with `[REDACTED]` **before parsing**, so secrets never reach the store, webview, or exports. JSON-pair rules replace only the value between quotes so redacted JSON lines still parse. Suffix-locked keys (`token`, `pwd`) require exact boundaries to avoid false positives like `prompt_tokens` or `pwd`-as-directory; fuzzy keys (`password`, `secret`, etc.) allow prefix/suffix flexibility. Also covers `Authorization: <scheme> <credential>` for any scheme (Basic/Token/Digest…), numeric JSON secrets (`"password": 123` → `"[REDACTED]"`, still valid JSON), whitespace-separated CLI flags (`--password x`), and `token@host` URL credentials (userinfo never spans `/`, so CDN paths like `pkg@1.0.0` are untouched). Uses `src/shared/regexSafety.ts` for ReDoS protection on custom patterns. Settings: `localLogViewer.redaction.*`.
- `src/core/lineCleaner.ts` — pure `cleanLine()` (ANSI/OSC/shell-integration stripping). CSI sequences **require ESC** — a bare `[` followed by a letter is text (`[INFO]`, `[Nest]`, `arr[i]`); only `[?NNNNh/l` bracketed-paste toggles are stripped without ESC. OSC sequences both BEL-terminated and ST-terminated (`\x1B\`). Preserves TAB (0x09) to protect TSV-style logs and tab-indented content.
- `src/core/sessionRegistry.ts` — `CaptureSession` records (`running` → `exited` | `stopped`, with `endedAt`, `exitCode`, `restart()`). Ended sessions stay listed until `pruneEnded()` (dashboard Clear). `activeCount` counts running only (status bar, stop-all). Sources call `end()`, not `remove()`, when a capture finishes.
- `src/core/config.ts` — typed accessors for the `localLogViewer.*` settings.
- `src/store/logStore.ts` — the log history (single source of truth, survives panel dispose). O(1) FIFO ring buffer; the cap is a plain number (`setLimit()` on config change — never read settings per line). Maintains indexes kept consistent on eviction: `findById`, `byCorrelation`, `byTrace`, `bySession`, `levelCounts` — the MCP tools use them when present (`ReadonlyLogStore` declares them optional so test fakes with only `getAll()` still work).
- `src/events/logEventBus.ts` — `vscode.EventEmitter<LogEntry>` fan-out for live entries.
- `src/store/commandStore.ts` — saved commands in `workspaceState` (MRU, deduped, cap 20, `replace()` for in-place edit).
- `src/ui/projectScripts.ts` — vscode-free `readProjectScripts(folder)` (package.json scripts, pre/post hooks hidden) + package manager from the lockfile. `pickCommand()` lists them per workspace folder and returns `{ command, cwd }`; scripts outside the first folder are not saved (saved commands always run in the first folder).
- `src/ui/commandPicker.ts` — `pickCommand()` (run flow) and `manageSavedCommands()` (edit/remove QuickPick).
- `src/mcp/` — the embedded MCP server for coding agents. `mcpProtocol.ts` (pure JSON-RPC/MCP dispatcher) and `mcpTools.ts` (nine read-only tools over structural deps; reuses the shared search grammar; `wait_for_logs` long-polls the event bus and releases its slot when the client disconnects — the HTTP layer passes an `AbortSignal` through `dispatchMcpMessage` → `callTool`; browse tools fill their token budget from the newest entries) must **never import vscode at runtime** — only `import type`. `mcpServerManager.ts` owns the `node:http` lifecycle (127.0.0.1, Bearer token persisted in `SecretStorage`, Origin validation, body cap, prompt shutdown). `mcpVsCodeProvider.ts` feature-detects the VS Code ≥1.101 MCP provider API through local structural types (engines stay ^1.75). `mcpSetup.ts` builds the copy-paste snippets.
- `src/shared/regexSafety.ts` — extracted pure regex compilation with ReDoS protection: length cap, a deterministic structural check (`isStructurallySafe`: star height ≤ 1 — no repeated group containing a quantifier or alternation, no backreferences, bounded `{n,m}`), then a time-boxed probe as a second layer. The probe alone is not enough: it runs synchronously, so a catastrophic pattern would hang inside it. Reused by `src/core/redactor.ts` for user-supplied custom redaction patterns to prevent catastrophic backtracking. Also reexported by `search.ts` for backward compatibility.
- `src/shared/timestamp.ts` / `src/shared/logfmt.ts` — pure helpers: epoch/ISO/text-prefix timestamp normalization (`normalizeTimestamp`, `extractTextTimestamp`) and logfmt parsing (`parseLogfmt`, strict enough that URLs and prose with one `=` stay plain text).
- `src/shared/stackFrames.ts` — pure `parseStackFrame()` (Node incl. `file://`/webpack URLs, Python, Java/Kotlin, .NET, Go; runtime internals like `node:` are not frames), `isLibraryFrame()`, `firstAppFrame()`. Shared by the webview (clickable frames) and the host (Problems).
- `src/shared/search.ts` — the **pure query engine** (parseQuery/matchesQuery/compileSafeRegex/parseDateTimeValue/parseSinceValue), shared by the webview filter and the MCP tools. DOM-free and vscode-free. Now reexports `compileSafeRegex` from `regexSafety.ts`.
- `src/logDashboard.ts` — `LogDashboard` is a **singleton** webview panel and a pure view: subscribes to the bus and forwards live entries in **batches** (`addLogs`, every 50 ms or 500 entries — never one message per line), serves history from the store (`loadHistory` carries the cap so the webview mirrors it), builds the HTML with a strict CSP (crypto nonce'd script tag).
- `src/logParser.ts` — `LogParser.parseLine()` turns a raw string into a `LogEntry`. Tries, in order: an injected `[LVL:LEVEL] ...` marker, then `JSON.parse` (level from `level`/`severity`/`levelname`/`lvl`/`@l`/`log.level` with name aliases like `warning`/`fatal`/`notice` and **numeric levels** from Pino/Bunyan: 10→TRACE … 60→ERROR; `status` counts only when non-numeric, since it is often an HTTP code; timestamps normalized to ISO by `src/shared/timestamp.ts`, which infers epoch s/ms/µs/ns — Pino's `time` is epoch **ms**), then the keyword heuristic (prefix level token first, then whole words, ignoring "0 errors"-style negations). Also exports `detectLevel()` — the **single** level-detection heuristic shared by the parser fallback and the terminal coloring in `captureManager.ts`.
- `src/models/logEntry.ts` — the `LogEntry` / `LogLevel` shared types (incl. `redacted`, `sessionId`).

**Webview (TypeScript, bundled by esbuild into `media/`):**
- `src/webview-src/lib/logModel.ts` — pure `LogModel` (DOM-free, tested by `test/test-webview-model.js`): owns logsData / filteredIndexes / level counts / cap trimming / id→index, mutating the shared `UiState` so `virtualList.ts` and `histogram.ts` keep reading `state.logsData`. `main.ts` must go through it rather than editing those arrays directly.
- `src/webview-src/lib/suggest.ts` — pure `FieldIndex` (fields + top values learned from entries, capped) and `suggest(input, cursor, index)` for the search autocomplete. `lib/filter.ts` `extractViewFlags()` strips webview-only flags (`is:bookmarked`) and value-less `field:` tokens before the shared grammar sees the query; `ViewFilterExtras` adds the session-chip and bookmark narrowing.
- `src/webview-src/main.ts` — orchestrator: DOM wiring, persisted-state restore, message handling, filters/search. Feature modules (`virtualList.ts`, `histogram.ts`, `detailPanel.ts`) receive deps/callbacks from main — no cross-imports between them. `lib/format.ts` and `lib/filter.ts` are pure and DOM-free (plain-Node testable); the search grammar itself lives in `src/shared/search.ts`. Communicates back with `stopAll` / `clearLogs` / `pasteLogs` / `ready` / `openSource` / `stopSession` / `restartSession` messages. Rows render through `highlight.ts` (`renderHighlighted` — text nodes + `<mark>`, never innerHTML); `VirtualList.invalidate()` forces a re-render after search / time-mode / bookmark changes (rows otherwise rebind only when their index changes). Icons are `@vscode/codicons`, bundled by esbuild from `style.css` (`loader: .ttf → file`) into `media/codicon.ttf`. The webview trims `logsData` to the host cap, keeps level counts incrementally (never an O(n) scan per render), persists the selection by entry **id**, and re-windows on a `ResizeObserver`. Clear button uses 2-step confirmation ("Confirm?" for 2s, second click executes). Paste modal has focus trap, role=dialog, and returns focus to the button that opened it. Toolbar has "Add" group (paste button) and "Actions" group (export/clear/stop).
- `src/webview-src/style.css` — styling, uses VS Code theme CSS variables.
- `src/shared/protocol.ts` — the typed postMessage protocol, imported by BOTH sides.

### Things that will bite you

- **Webview assets are built to `media/` by `esbuild.mjs`** (gitignored — never edit `media/` by hand). Three coupling points must stay in sync: the esbuild entry points/outdir, the `asWebviewUri(... 'media', ...)` calls in `logDashboard.ts`, and `media/**` in `package.json` `files`. esbuild does not type-check — `npm run compile` also runs `tsc -p tsconfig.webview.json` (noEmit). The host tsconfig has **no DOM lib**; only `src/shared/` and `src/models/` are shared between host and webview. Packaging uses only the `files` allow-list — `vsce` refuses to build if a `.vscodeignore` is reintroduced alongside it, so don't add one back.
- **Process termination is cross-platform and deliberate.** Stopping a capture escalates SIGINT → SIGTERM → SIGKILL across the whole process tree: `taskkill /T /F` on Windows, process-group kill (`process.kill(-pid)`, enabled by `detached: true` on spawn) with a ps-table PPID-walk fallback on POSIX (a single `ps -A -o pid=,ppid=` — BSD/macOS `ps` has no `--ppid`). `mutedProcessPids` suppresses dashboard output from a process that is being intentionally killed. Preserve this when touching capture code, or child processes (e.g. `npm run dev`'s subprocesses) will leak.
- **Redaction runs before parsing.** Any new redaction pattern must keep a JSON line valid JSON (replace only the value characters, never quotes/structure), or redacted JSON logs will fall back to plaintext parsing and lose level/timestamp.
- **Closing the dashboard does NOT stop captures** — sessions keep running (sidebar + status bar give control). Don't reintroduce `stopAllCaptures` into `LogDashboard.dispose()`.
- **`src/mcp/mcpProtocol.ts` and `src/mcp/mcpTools.ts` must never import vscode at runtime** (structural interfaces + `import type` only) — the plain-Node test suites `require` their compiled output and fail at load time otherwise. `test/test-mcp-server.js` stubs the vscode module via a `Module._load` hook to boot the real manager; keep the manager's vscode surface small so that stub stays trivial.

## Contributes

- **Commands**: `openDashboard`, `runAndCapture`, `followFile` (accepts an optional `Uri` from the explorer context menu), `manageCommands`, `runLastCommand` (modal confirmation, gated by `localLogViewer.confirmRunLastCommand`), `stopAllCaptures`, `exportLogs`, `pasteLogsFromClipboard` (palette-visible, prompts for optional label, clipboard → auto-open dashboard → import). Hidden/programmatic: `pasteLogs` (webview modal → import with custom label, invoked via postMessage), `addNewCommand` (sidebar "Add new command" item). Sidebar item commands (`stopCapture`, `runSavedCommand`, `editSavedCommand`, `deleteSavedCommand`) take tree items as args and are hidden from the palette via `menus.commandPalette` `"when": "false"`. **UX Note**: Paste is reachable from 3 places — toolbar button (📋 Paste), empty-state button, and sidebar/palette command — all wired to the same modal with optional custom label and focus trap. Export/Clear/Stop are in the "Actions" toolbar group; Paste is in the "Add" group, separate from log management.
- **Sidebar**: Activity Bar container `localLogsConsole` → view `localLogsConsole.captures`, fed by `src/sidebar/capturesTreeProvider.ts` (sections from `SessionRegistry` + `CommandStore`; always includes `DashboardItem` (📊) at root if there are any captures or commands; "Saved Commands" section now mirrors that same condition so "➕ Add new command" item is reachable even with zero saved commands; returns `[]` root when both empty so `viewsWelcome` shows onboarding). `CommandStore.onDidChange` uses plain callbacks, NOT `vscode.EventEmitter`, so the store stays requireable from plain-Node tests. Dashboard icon click auto-opens the dashboard panel alongside sidebar.
- **Export**: `src/export/serialize.ts` is the pure part (tested by `test/test-exporter.js`); `src/export/logExporter.ts` owns the VS Code flow (filtered scope uses the `requestVisibleIds`/`visibleIds` webview round-trip on `LogDashboard`).
- **Dashboard dispose does NOT stop captures** (since 0.3.0) — they keep running under sidebar/status-bar control; a one-time notice (`globalState`) explains this.
- Keybindings: `ctrl/cmd+alt+l` (dashboard), `ctrl/cmd+alt+shift+l` (run last), `ctrl/cmd+alt+r` (`restartLastCapture` — `SessionRegistry.restart()` stops a running session first). `openSource` is a hidden command used by the webview. The panel is restored after a restart by a `WebviewPanelSerializer` (`activationEvents: onWebviewPanel:logDashboard`). Explorer context menu follows `.log`/`.txt`/`.log.N` files.
- **MCP**: `copyMcpSetup` command, `mcpServerDefinitionProviders` contribution (ignored by VS Code <1.101), server enabled by default. `McpServerManager` lives in the composition root like the other services; config changes under `localLogViewer.mcp` trigger `syncWithConfig()`.
- **Settings** live under the `localLogViewer.*` namespace (`historyLimit`, `tail.seedBytes`, `redaction.enabled|useDefaultPatterns|patterns`, `confirmRunLastCommand`, `capture.inheritEnvironment`, `capture.debugSessions`, `problems.enabled`, `mcp.enabled`, `mcp.port`) — add new settings there and read them via `src/core/config.ts`.
